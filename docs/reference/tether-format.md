# The `.tether` project file format

**Who this page is for.** Anyone who has been handed a `.tether` file and wants to read it
with plain `h5py`, in another language, or in a script that must keep working across Tether
releases. It assumes you can run a Python script and know what an HDF5 group and dataset are.

This page is the reference for the **internal** layout of a project file only. This page
calls that HDF5 layout the **store**, and uses "project file" for the `.tether` file itself. What
Tether *writes out* (SMD-HDF5 hand-off, CSV/Parquet tables, plot exports) is a
separate surface, described in [Exports (files, columns, units)](exports.md).

A `.tether` file is an ordinary HDF5 file. There is no proprietary container, no
separate index file, and no compression scheme beyond stock gzip on the bulk arrays.

The format has **two layers**, and they carry different guarantees:

- The **frozen skeleton** — the 14 group paths (the root plus the 13 top-level
  groups), the six compound `table` dtypes and the three root attributes — is
  declared in exactly one place,
  `src/tether/io/schema.py`, and a machine-checked copy of it is committed as
  `schema/schema_frozen.json`. This site serves that file, unchanged, as
  [`tether-schema.json`](tether-schema.json), so each version of these pages links
  to the schema of the same version. That manifest is generated by
  `scripts/dump_schema.py`, which runs `tether.io.schema.build_manifest` against a
  throwaway `create_project` store, so it cannot drift from the code. Where this page
  and that manifest disagree about the skeleton, **the manifest is right and this
  page is a bug**.
- Everything a pipeline stage writes *later* — `/traces/*`, `/patches/*`,
  `/settings/*`, `/idealization/{model}`, `/features/table`, `/conditions/categories`,
  `/movies/layouts`, `/calibration/*`, `/models/*` — is additive per-record data declared
  by the module that writes it. None of it appears in the manifest, so the manifest
  cannot arbitrate it: the writer named in each section below is the authority. Note the `/*`: the **container
  groups** these live in are themselves part of the frozen skeleton above, and only
  their contents are additive.

Every claim below names the module, constant, or writer behind it.

## Opening a store

```python
import h5py

with h5py.File("experiment.tether", "r") as f:
    assert f.attrs["format"] == "tether-project"
    print(int(f.attrs["schema_version"]))          # 3
    mols = f["/molecules/table"][:]                # a structured (compound) array
    print(mols["molecule_key"][0].decode("utf-8")) # vlen UTF-8 reads back as bytes
```

Tether's own validation entry point is
`tether.io.schema.assert_is_compatible_project(path)`, which checks, in this order:
the file is readable HDF5; the root `format` attribute is `tether-project`; a
`schema_version` stamp exists; the frozen top-level skeleton is present (so a foreign
*or truncated* HDF5 file is rejected rather than silently accepted); and that version
is not newer than the running app. It returns the on-disk `schema_version`. The order
matters when you are diagnosing a rejection: a stamp-less file fails on the stamp
before the skeleton is ever inspected.

String fields are HDF5 **variable-length UTF-8**
(`h5py.string_dtype(encoding="utf-8")`, the [`_str()`](https://github.com/bioedca/tether/blob/main/src/tether/io/schema.py) helper in
`src/tether/io/schema.py`). h5py hands them back as `bytes` — decode them yourself.

## What is frozen, and what that means for your reader

The entire group skeleton was forward-declared and version-stamped when the schema was frozen
and is **additive-only** thereafter
([ADR-0005](../adr/0005-m0-schema-freeze.md)). Concretely, the freeze covers:

- the 14 group paths listed on this page;
- the six compound `table` datasets, including **field order** — a compound dtype's
  on-disk layout is positional, so new fields may only be *appended*
  ([`_diff_compound`](https://github.com/bioedca/tether/blob/main/src/tether/io/schema.py) in `src/tether/io/schema.py` requires the golden field sequence
  to remain an exact prefix of the current one);
- each field's dtype and sub-array shape;
- each table's `maxshape` (all six are `(None,)` — 1-D and resizable);
- the presence and type of the three root attributes, plus the *values* of `format`
  and `schema_version`.

Those rules are enforced mechanically, not by review: the `schema-guard` CI job
(`.github/workflows/schema-guard.yml`) runs `python scripts/dump_schema.py --check`,
which fails a removal, rename, reorder or retype and passes an added group, dataset,
attribute or *trailing* table field. The release **policy** behind them is not
restated here:
[what each release may change](../stability.md#what-each-release-may-change) sets out
which release types may touch what, and
[the `.tether` on-disk format](../stability.md#2-the-tether-on-disk-format) lists which
parts of this page are a promise rather than a description.

What that means if you write your own reader:

> **Tolerate what you do not recognize.** Read compound tables **by field name**,
> never by positional index or a hard-coded record size, and ignore fields, datasets,
> groups and attributes you do not know — a later Tether release may add them without
> a `schema_version` bump. Conversely, you may rely on the **frozen skeleton** above —
> the group paths, the six tables' field names, dtypes and order, and the three root
> attributes (`app_version` only in a file whose writer stamped it — see the
> root-group section below) — continuing to exist unchanged for as long as
> `schema_version` stays `3`. That is exactly the set `schema-guard` mechanically
> enforces against the writer.

The additive payloads described further down (`/traces/*`, `/patches/*`,
`/settings/*`, `/idealization/{model}`, `/features/table`, `/calibration/*`) are
**documented convention, not part of the freeze**. Their **container groups are not**:
`/traces`, `/patches`, `/settings`, `/idealization`, `/features`, `/calibration` and
`/models` are all in the golden's `groups` list and in [`_CONTAINER_GROUPS`](https://github.com/bioedca/tether/blob/main/src/tether/io/schema.py)
(`src/tether/io/schema.py`), so a file missing any one of them is rejected by
`assert_is_compatible_project` as not a project — a **required** group your reader may
rely on, even when it is empty. Only what is *inside* them is unarbitrated:
`build_manifest` introspects a freshly created, empty store, so none of those child
names is in the golden and `diff_manifest` never compares them; renaming or retyping
one would pass `schema-guard` with `schema_version` untouched. They have been additive in practice, and `/features/table`
carries its own independent `feature_schema_version` precisely so its columns can
change without touching the store's `schema_version`. Pin your reader to the writer
module named in each section, and treat a missing or unfamiliar payload as normal.

`schema_version` is currently **`3`** (`SCHEMA_VERSION`, `src/tether/io/schema.py`).
Version 2 added the `/generations` table ([ADR-0136](../adr/0136-a-new-extraction-of-a-movie-is-a-new-trace-generation.md)),
and version 3 the `/sources` table ([ADR-0140](../adr/0140-a-source-registry-records-each-source-file-and-what-was-derived-from-it.md)).
A store stamped `1` has neither table and a store stamped `2` has no `/sources` table.

Each is still a complete project. It reads as generation 1 of each of its movies and as one
source record for each movie. The first write that adds a table also adds every other table of version 3. It keeps the
file as it was beside it, as `<stem>.v1-backup.tether` or `<stem>.v2-backup.tether`.

What a bump would mean for a file you already hold, and
what a non-additive change has to carry before one is allowed, are set out under
[Project file compatibility](../stability.md#project-file-compatibility); how a
covered name is retired is the
[deprecation policy](../stability.md#deprecation-policy) on the same page.

Two properties worth knowing before you build on the format:

- The store is a **superset of SMD**, the tMAVEN interchange model
  ([ADR-0002](../adr/0002-smd-superset-round-trip.md)): every SMD concept has a home
  here, plus the coordinates, patches, corrections and provenance SMD has no slot
  for. Round-trip fidelity is therefore a property of the data model, not of a
  converter.
- The `<file>.lock` single-writer marker is a separate **lock file**, not part of the
  in-HDF5 schema (`src/tether/io/schema.py` module docstring); `create_project`
  never writes it.

## A freshly created project is nearly empty

`tether.io.schema.create_project(path)` writes the whole skeleton and nothing else:
13 top-level groups, six **zero-row** compound tables, and three root attributes.
Everything else on this page is *data* written later by a specific pipeline stage.
(Do not treat the file's *size* as a format property — the same skeleton measures
12,950 bytes under HDF5 2.0.0 and 13,164 under 1.14.x. Only the structure is fixed.)

The `/traces` and `/patches` **groups** always exist — they are part of the validated
skeleton ([`_CONTAINER_GROUPS`](https://github.com/bioedca/tether/blob/main/src/tether/io/schema.py)), and a file missing one is rejected as not a project.
What a reader must not assume is that anything is *inside* them: no `/traces/*` or
`/patches/*` dataset, no `/features/table`, and no `/idealization/{model}` is
guaranteed to be there.

| Path | In a fresh store | First written by |
|---|---|---|
| `/movies/table`, `/molecules/table`, `/conditions/table`, `/labels/table`, `/generations/table`, `/sources/table` | yes, 0 rows | `create_project` (`src/tether/io/schema.py`) |
| `/calibration`, `/traces`, `/patches`, `/idealization`, `/settings`, `/features`, `/models` | yes, empty groups | `create_project` |
| `/calibration/<calibration_id>/…` | no | `write_calibration` (`src/tether/imaging/calibrate.py`) |
| `/movies` and `/molecules` rows, `/movies/layouts/<movie_id>`, `/traces/*`, `/patches/*`, `/settings/extraction`, `/generations` rows | no rows / absent | `write_extraction` (`src/tether/imaging/extract.py`) |
| `/generations/archive/<movie_id>/<generation>` | absent | `write_generation` (`src/tether/imaging/extract.py`), run by `reextract_movie` (`src/tether/project/extract.py`) |
| `/movies/metadata/<movie_id>` | absent | `extract_movie` (`src/tether/project/extract.py`); changed by `tether.project.movie_metadata` |
| `/idealization/{model}` | no | `write_idealization_model` (`src/tether/project/idealize.py`) |
| `/labels` rows | 0 rows | `set_curation_label` (`src/tether/project/labels.py`) |
| `/labels/reject_log` | absent | `reject` / `unreject` (`src/tether/project/labels.py`) |
| `/settings/leakage`, `/settings/gamma`, `/settings/correction`, `/settings/batch` | no | `tether.project.leakage` / `.gamma` / `.correct` / `.batch` |
| `/conditions` rows, `/conditions/categories/<condition_id>`, `/settings/condition_audit` | 0 rows / absent | `tether.project.conditions` |
| `/settings/molecule_audit` | absent | `set_category` / `clear_category` / `set_analysis_window` / `reset_analysis_window` (`src/tether/project/molecule_edits.py`) |
| `/settings/lock_takeovers` | absent | `record_takeover` (`src/tether/project/lock_takeovers.py`), called by the application after a Recover or Take over |
| `/features/table` | no | `compute_features` (`src/tether/project/features.py`). Each analysis-window writer deletes it when it changes a row the table holds. The `/features` section names them. |
| `/settings/analysis_only` | no | `import_analysis_only_project` (`src/tether/project/analysis_import.py`) |
| `/settings/jobs`, `/settings/recorded_inputs`, `/settings/stale_marks` | absent | `submit_job` / `record_inputs` / `set_stale_marks` (`src/tether/project/jobs.py`) |
| `/sources` rows | 0 rows | `register_source` / `relink_source` (`src/tether/project/sources.py`) and the checksum job (`src/tether/services/sources.py`) |
| `/settings/correction_transitions` | absent | `send_event` (`src/tether/project/correction_states.py`) |
| `/settings/gamma_contributors`, `/settings/gamma_contributor_decisions` | absent | `compute_gamma` (`src/tether/project/gamma.py`) / `set_gamma_contributor` (`src/tether/project/gamma_contributors.py`) |
| `/settings/approvals` | absent | `record_approval` (`src/tether/project/approvals.py`), called by `tether approve` and by a recipe policy |
| `/models/<condition_id>` | no | `record_model_reference` (`src/tether/project/model_artifact.py`) |

`write_extraction` is not the only writer of `/molecules` rows and `/traces`. Four
shipped provenances produce a populated store, and they differ in what they fill in.
The rest of this page describes the native-extraction case unless it says otherwise:

| Store provenance | Writer | What differs |
|---|---|---|
| Native extraction | `write_extraction` (`src/tether/imaging/extract.py`) | The fullest record: `/movies` rows, coordinates, all six `/traces` layers, `/patches` — but only for a movie that yielded at least one molecule; see [`/traces`](#traces-the-integrated-intensity-arrays) for the zero-molecule case. |
| Deep-LASI reconstruction | `reconstruct_project` (`src/tether/project/reconstruct.py`) | Also goes through `write_extraction`, so the `/movies`, `/molecules`, `/traces` and `/patches` layout is the same — but the trace values are the legacy `.mat` series copied verbatim, **not** an integration this build performed, and **no calibration is written**: `reconstruct_project` never calls `write_calibration`, so `/calibration` stays empty whatever the caller passes. The shipped GUI caller — the wizard is the only caller; no `tether` subcommand reconstructs — additionally leaves the calibration key and channel geometry unset ([`_movie_metadata`](https://github.com/bioedca/tether/blob/main/src/tether/gui/deeplasi_executor.py), `src/tether/gui/deeplasi_executor.py`), so in practice `/movies.calibration_id` is `""` and the crop/rotation/flip fields are all zero. |
| Analysis-only import | `import_analysis_only_project` (`src/tether/project/analysis_import.py`) | No `/movies` rows, `movie_id = ""`, `donor_xy`/`acceptor_xy` `NaN`, `/patches` empty, only the two background-subtracted (`corrected`) `/traces` layers. |
| Subset export | `export_subset_tether` (`src/tether/project/export.py`) | A new store: `/molecules` rows copied verbatim (so `movie_id` survives as a **dangling** key), no `/movies` rows, background-subtracted (`corrected`) `/traces` only unless `include_raw=True`. |

`create_project` opens the file with `track_order=True` and creates every skeleton
group with it, and the later `/settings/*`, `/calibration/<id>` and
`/conditions/categories` writers do the same, so those links are stored in creation
order. The promise is **not** store-wide: the per-model `/idealization/<name>` groups
and the `priors` subgroup inside them are created without `track_order`
(`write_idealization_model`, `src/tether/project/idealize.py`; the copy in
[`_copy_idealization`](https://github.com/bioedca/tether/blob/main/src/tether/project/export.py), `src/tether/project/export.py`), so their members fall back to
HDF5's default ordering. Either way, `h5py.Group.visit` iterates **alphabetically**.

## Type notation used below

The Type column uses the same canonical names as `schema/schema_frozen.json`, which
deliberately drops byte order so the manifest is platform-independent
([`_canonical_scalar`](https://github.com/bioedca/tether/blob/main/src/tether/io/schema.py)): `i1`, `i4`, `i8` are signed integers of 1/4/8 bytes, `f8` is a
64-bit float, and `str:utf-8` is a variable-length UTF-8 string. The dtypes actually
declared in `src/tether/io/schema.py` are the little-endian spellings `<i4`, `<i8`,
`<f8` (and `i1`, which has no byte order).

## `/` — the root group

Three attributes. `create_project` always writes `format` and `schema_version`; the
third is stamped **by default but optional** (see below):

| Attribute | Type | Value | Frozen |
|---|---|---|---|
| `format` | `str` | `tether-project` (`FORMAT_TAG`) | name, type **and value** |
| `schema_version` | `int` | `3` (`SCHEMA_VERSION`) | name, type **and value**, monotonic |
| `app_version` | `str` | the writing Tether version, e.g. `0.8.1.dev16+g…` | name and type only |

`app_version` is provenance, not structure, and what is frozen is the **writer's**
declaration rather than every file: `create_project(path, stamp_app_version=False)`
omits the attribute and `assert_is_compatible_project` never looks for it, so a store
without it is valid. Read it as `f.attrs.get("app_version")` and never reject a file
for its absence. The policy — including why its *value* is excluded from the manifest
— is
[the `.tether` on-disk format](../stability.md#2-the-tether-on-disk-format) section of
the stability page.

Subset exports stamp four **additional** root attributes onto the destination file —
`tether_subset_of`, `tether_subset_created_utc`, `tether_subset_include_raw`,
`tether_subset_n_molecules` (`src/tether/project/export.py`) — a good example of the
additive rule in practice: your reader should expect unknown root attributes.

## `/movies` — one row per source movie

Group holding `/movies/table`, a resizable 1-D compound dataset (`MOVIES_DTYPE`,
20 fields). `write_extraction` appends one row per movie. `extract_movie` writes the first row
of a new project, and `add_movie_to_project` (`src/tether/project/extract.py`) appends each
later movie. A Deep-LASI acquisition goes in through `reconstruct_project` and
`add_reconstruction_to_project` (`src/tether/project/reconstruct.py`).

Re-appending an existing `movie_id` is refused. `add_movie_to_project` also refuses a movie
whose `sha256` is already in a row, and `write_extraction` refuses any molecule whose
`molecule_key` is already in `/molecules`
([ADR-0117](../adr/0117-a-movie-is-appended-to-a-project-once-under-its-writer-lock.md)).
For a new trace generation, `write_generation` updates the movie's row in place
with the new inputs and keeps its `frame_time`. The previous row stays in
[the generation archive](#generations-the-trace-generations-of-each-movie).
`file_size` + `mtime` + `offline_flag` are the **metadata-only fast signature**: a relocation/staleness check that reads zero bytes
of the movie and therefore never hydrates a cloud placeholder.

| Field | Type | Shape | Meaning / units |
|---|---|---|---|
| `movie_id` | `str:utf-8` | scalar | Movie identity within this store; the CLI writes `mov-<uuid4>` (`src/tether/project/extract.py`). |
| `uri` | `str:utf-8` | scalar | Source movie path as text; `""` when unknown. |
| `sha256` | `str:utf-8` | scalar | 64-char hex SHA-256 of the whole movie file ([`_hash_movie`](https://github.com/bioedca/tether/blob/main/src/tether/project/extract.py)); seeds every `molecule_key`. |
| `file_size` | `i8` | scalar | `Path.stat().st_size`, **bytes**. |
| `mtime` | `f8` | scalar | `Path.stat().st_mtime`, **POSIX epoch seconds**. |
| `offline_flag` | `i1` | scalar | Cloud-placeholder / offline marker. Reserved: every shipped writer leaves it `0`. |
| `n_frames` | `i4` | scalar | Frame count of the movie (validated `>= 1`). |
| `height` | `i4` | scalar | Full-frame height, **pixels**. |
| `width` | `i4` | scalar | Full-frame width, **pixels** — the whole frame, before the two-channel split. |
| `pixel_dtype` | `str:utf-8` | scalar | On-disk pixel dtype string, e.g. `>u2` (`src/tether/io/movie.py`). |
| `byteorder` | `str:utf-8` | scalar | `>` (big-endian) or `<` (little-endian). |
| `frame_time` | `f8` | scalar | **Seconds per frame.** The writer stores whatever the caller's `MovieMetadata` holds (default `0.0`), and both shipped writers — `tether.project.extract` and the Deep-LASI reconstruction's [`_movie_metadata`](https://github.com/bioedca/tether/blob/main/src/tether/gui/deeplasi_executor.py) (`src/tether/gui/deeplasi_executor.py`) — take it from the movie TIFF's ImageJ `finterval` tag, and only when that is finite and positive ([`_read_frame_time`](https://github.com/bioedca/tether/blob/main/src/tether/io/movie.py), `src/tether/io/movie.py`); `0.0` otherwise. A **Deep-LASI reconstruction** is no exception: it builds this row from the raw TIFF as well, and the shipped `.tdat`/`.mat` decode reads no `FrameTime`, so a reconstructed store does **not** preserve a Deep-LASI timebase. |
| `head_tail_hash` | `str:utf-8` | scalar | Reserved partial-content digest for the fast signature; no shipped writer sets it (stays `""`). |
| `calibration_id` | `str:utf-8` | scalar | Join key into `/calibration`. |
| `donor_crop` | `i4` | `(4,)` | `[y1, x1, y2, x2]`, **1-based inclusive** pixel bounds (`src/tether/imaging/split.py`). All-zero means full frame / unspecified. |
| `acceptor_crop` | `i4` | `(4,)` | Same convention, acceptor channel. |
| `donor_rotation_deg` | `i4` | scalar | Channel rotation in **degrees**, one of `{0, 90, 180, 270}`. |
| `acceptor_rotation_deg` | `i4` | scalar | Same, acceptor channel. |
| `donor_flip` | `i1` | `(2,)` | `[vertical, horizontal]` flip flags, `0`/`1`. |
| `acceptor_flip` | `i1` | `(2,)` | Same, acceptor channel. |

The group also holds an additive child, `/movies/layouts/<movie_id>`: the **channel layout**
the movie was split by (#908), written by `write_layout_record` in `src/tether/imaging/layout.py`. Each
record is an empty group with attributes only:

- `version` (int): `1`. A reader refuses a newer version (`read_layout_record`).
- `kind` (str): `side-by-side`, `top-bottom` or `rectangles`.
- `donor` and `acceptor` (str): the donor and the acceptor half — `left`/`right` or
  `top`/`bottom` — and `""` for `rectangles`.
- `donor_rect` and `acceptor_rect` (int32 `[y1, x1, y2, x2]`, 1-based inclusive): for
  `rectangles` only.

The record states the layout. The crops it resolved to for this frame size are the
`donor_crop` and `acceptor_crop` fields above. The native `tether extract` path writes one for
every movie, the default `side-by-side` / `left` included. A store written before #908, a
Deep-LASI reconstruction, and an extraction that took its split from an imported `.tmap` have
no record for the movie. For those, read the crop fields instead.

The group also holds a second additive child, `/movies/metadata/<movie_id>`. It is one group
with no datasets for each movie. Its attributes record three values, each with its
**origin**: `file` (read from the movie), `user` (given by a person) or `unknown`
(`src/tether/project/movie_metadata.py`, #911). It does not change `frame_time` above,
which keeps the value from the file.

| Attribute | Type | Meaning / units |
|---|---|---|
| `frame_time` | `float` | **Seconds per frame** in use: the file's value, or the one the user gave; `0.0` unknown. |
| `frame_time_origin` | `str` | `file`, `user` or `unknown`. |
| `frame_time_verified` | `bool` | True only for a file value, or after the user confirmed a given value in a separate action (`confirm_frame_time`); giving a value clears it. |
| `pixel_size_um` | `float` | **Micrometres per pixel**: the ImageJ resolution when its unit is µm, the pixels are square and the resolution is not the `1/1` placeholder, or the user's value; `0.0` unknown. |
| `pixel_size_origin` | `str` | `file`, `user` or `unknown`. |
| `channel_roles_origin` | `str` | Where the donor/acceptor assignment of `donor_crop`/`acceptor_crop` came from: `file` for an imported `.tmap`, `user` for a native extraction (`--donor-side`). |

`extract_movie` writes the group. Some rows have no group: a store written before #911,
or one from the Deep-LASI reconstruction or the analysis-only import. Such a row reads
(`read_movie_metadata`) as follows. A positive `frame_time` has origin `file` and is
verified, because that field has only ever been filled from the ImageJ `finterval`. A
`frame_time` of `0.0` is `unknown`. The pixel size and the channel roles are `unknown`.

## `/molecules` — one row per molecule

Group holding `/molecules/table` (`MOLECULES_DTYPE`, 21 fields). This is the spine
of the store: **row `i` of `/molecules/table`, of every `/traces/*` array and of
every `/patches/*` array is the same molecule** — the join is positional, asserted
by [`_validate_alignment`](https://github.com/bioedca/tether/blob/main/src/tether/imaging/extract.py) in `src/tether/imaging/extract.py`.

Later stages mutate columns of existing rows; they never change the structure.
Photobleach detection rewrites `bleach_frames` and `analysis_window`, the leakage /
gamma / correction stages write `alpha`, `gamma`, `correction_method` and
`correction_confidence`, curation writes `curation_label`, a condition re-key
rewrites `condition_id`, and the per-molecule setters in
`src/tether/project/molecule_edits.py` write `category` and `analysis_window`.

| Field | Type | Shape | Meaning / units |
|---|---|---|---|
| `molecule_id` | `str:utf-8` | scalar | Stable per-row identity, `mol-<uuid4 hex>`. **Unique**, so this is the correct join key for per-row data. |
| `molecule_key` | `str:utf-8` | scalar | Cross-file content identity, 64-char hex SHA-256. Deterministic across runs and platforms. See the derivations below. |
| `movie_id` | `str:utf-8` | scalar | Foreign key into `/movies/table`. `""` in an analysis-only import, and **dangling** in a subset export (which carries no `/movies` rows) — resolve it defensively. |
| `donor_xy` | `f8` | `(2,)` | Sub-pixel `[x, y]` donor (reference-channel) centroid, in **movie pixels** of the donor sub-image. |
| `acceptor_xy` | `f8` | `(2,)` | Sub-pixel `[x, y]` acceptor read position, the donor position mapped through the registration map, in **movie pixels**. |

A curator sets it with `set_analysis_window`, which clamps the request into `frame_range` (bounded by `[0, n_frames]`) by the SMD-import rule ([`_resolve_windows`](https://github.com/bioedca/tether/blob/main/src/tether/project/analysis_import.py), `src/tether/project/analysis_import.py`), and restores it with `reset_analysis_window`. | `correction_confidence` | `f8` | scalar | A **provenance flag, not a confidence interval**: `1.0` when a real correction was applied, `0.0` on apparent-E fallback, `NaN` before any pass. |
| `curation_label` | `i4` | scalar | Signed codec `CurationLabel` (`src/tether/project/labels.py`): `0` uncurated, `1` accept, `-1` reject. Mirrors the most recent **human** label only. |
| `category` | `str:utf-8` | scalar | Editable per-condition category value, independent of accept/reject. `""` at extraction. Stored by **name**. `set_category` accepts only a name in the condition's `/conditions/categories/<condition_id>` list, and `clear_category` writes `""`. |
| `quality_class` | `f8` | scalar | Read-only ML ranker output, dimensionless. `NaN` when none; no shipped ML path writes it yet. |
| `condition_id` | `str:utf-8` | scalar | Current foreign key into `/conditions/table`; rewritten by a re-key. |
| `condition_id_provisional` | `str:utf-8` | scalar | The filename-derived condition id, retained verbatim across any re-key. |
| `source_filename` | `str:utf-8` | scalar | Original acquisition filename the molecule came from. |
| `tags` | `str:utf-8` | scalar | Comma-joined tag string; `""` when none. The pipeline emits two tags — see below. |

> **A narrowed `analysis_window` is not a provenance signal.** In a natively extracted
> store the analysis window starts equal to `frame_range`, so a narrower one does mean
> photobleach detection or a curator edit. That inference breaks on an **analysis-only
> import**: [`_normalize_source`](https://github.com/bioedca/tether/blob/main/src/tether/project/analysis_import.py) reads the SMD's tMAVEN `pre_list`/`post_list` and
> [`_build_molecule_rows`](https://github.com/bioedca/tether/blob/main/src/tether/project/analysis_import.py) writes them straight into `analysis_window`
> (`src/tether/project/analysis_import.py`), so a *freshly imported* row can already be
> narrower than `frame_range` with `bleach_frames` still `-1` and `curation_label`
> still `0`. And because the auto-refine fires only on an analysis window that still equals
> `frame_range`, a later `compute_photobleach` leaves those imported analysis windows alone. On
> a real 2-molecule import with `pre_list = [3, 0]` / `post_list = [30, 40]` over 40
> frames, the rows read `analysis_window` `[3, 30]` and `[0, 40]` against `frame_range`
> `[0, 40]`, and `compute_photobleach` reported `n_windows_autoset=1` — it refined only
> the second row. To tell the cases apart, read `/settings/analysis_only` or the
> `round-trip-unavailable` tag, not the analysis window.

### `/molecules/acceptor_detected` — the colocalization flag

An `int8` dataset beside the table, one value per row of `/molecules/table`, in the same
order ([ADR-0127](../adr/0127-colocalization-policy-partner-in-both-by-default-or-donor-anchored.md)).
`1` means an acceptor spot was detected within `coloc_distance` of the mapped position.
`0` means none was. `-1` means the extraction did not record it.

A project extracted before the flag existed has no dataset. A project that later gained
rows can have a dataset shorter than the table. Both read as `-1` for the rows the dataset
does not cover
([`read_acceptor_detected`](https://github.com/bioedca/tether/blob/main/src/tether/imaging/extract.py)).
A dataset longer than the table is refused on the next append. A Deep-LASI reconstruction
writes `-1`, because its molecules are not detected. A subset export carries the flag of
each molecule it copies.

The rule of each movie is the `colocalization` key of its profile on
`/settings/extraction/movies` (below). It is `partner-in-both`, under which every kept
molecule has flag `1`, or `donor-anchored`. A profile without the key reads as
`donor-anchored`
([`read_colocalization_policies`](https://github.com/bioedca/tether/blob/main/src/tether/imaging/extract.py)).
Such a profile was written before the rule could be chosen, or by a Deep-LASI
reconstruction.

### Two sentinels and two derivations worth reading twice

**`bleach_frames`.** `-1` ([`_UNDETECTED_FRAME`](https://github.com/bioedca/tether/blob/main/src/tether/imaging/extract.py), `src/tether/imaging/extract.py`) is
what extraction and analysis-only import write *before anyone has looked*: it means
the photobleach detector has not run for that row, not that it ran and found nothing.
After `compute_photobleach` (`src/tether/project/photobleach.py`) a channel that does
**not** bleach within the trace is recorded as `frame_range[1]` — the trace end — so
the comparison you want is against `frame_range`, never against `-1`. (`-1` also
survives on a row with no valid native frames, which the detector skips.) On a real
40-frame store, one bleaching and two non-bleaching molecules read
`[[30, 20], [40, 40], [40, 40]]` against `frame_range` `[[0, 40], [0, 40], [0, 40]]`.

**`tags`.** Two tags are emitted by shipped code:

| Tag | Constant | When |
|---|---|---|
| `low-confidence-registration` | `LOW_CONFIDENCE_TAG` (`src/tether/imaging/calibrate.py`) | The registration fit for that molecule exceeded the confidence gate. |
| `round-trip-unavailable` | `ANALYSIS_ONLY_TAG` (`src/tether/project/analysis_import.py`) | Stamped on **every** molecule of an analysis-only import — it is on every row of such a store. |

**`molecule_key`.** It is the cross-file join key everything downstream depends on,
and it is a pure content hash — no salt, no run state
([ADR-0016](../adr/0016-extraction-trace-store-layout.md)). The **first extraction**
derivation, from `molecule_key()` in `src/tether/imaging/extract.py`, is:

```python
q = round_half_away(donor_xy / MOLECULE_KEY_QUANTUM_PX).astype(np.int64)  # 0.1 px
payload = f"{movie_sha256}|{int(q[0])}|{int(q[1])}"
key = hashlib.sha256(payload.encode("utf-8")).hexdigest()
```

The 0.1 px quantum absorbs float-representation jitter. A split or subset keeps the
stored key. Two molecules can in principle quantize to the same coordinate. Join per-row
data on `molecule_id`.

An **analysis-only import** has no movie and no coordinates — `molecule_key()` would
in fact raise on its `NaN` `donor_xy` — so it uses a second derivation,
[`_analysis_only_molecule_key`](https://github.com/bioedca/tether/blob/main/src/tether/project/analysis_import.py) (`src/tether/project/analysis_import.py`), hashing the
source identity, the molecule's row index and the raw donor/acceptor trace bytes.
That variant *is* unique by construction.

A later extraction keeps the keys of carried
molecules ([ADR-0136](../adr/0136-a-new-extraction-of-a-movie-is-a-new-trace-generation.md)).
An unmatched site uses quantized raw camera coordinates and appends `|camera` to the hash
payload. It can join a newly found site in another copy across crops and generation numbers.
If the project's history already holds the camera key, the new payload also ends in `|g<n>`.
First-to-later joins use an earlier key carried by the recorded match. Read the stored key.

## `/conditions` — the structured experimental conditions

Group holding `/conditions/table` (`CONDITIONS_DTYPE`, 14 fields). The condition
**identity key** is (construct/variant, dye, ligand + concentration, buffer,
temperature, laser power); `date`, `replicate` and the source file deliberately vary
*within* one condition and are not part of the key
([ADR-0033](../adr/0033-condition-identity-and-rekey.md)). `condition_id` is derived
from that key as `cond-<first 12 hex of its sha256>`
(`ConditionKey.condition_id()` in `src/tether/io/filename.py`).

| Field | Type | Shape | Meaning / units |
|---|---|---|---|
| `condition_id` | `str:utf-8` | scalar | `cond-<12 hex>`, the content hash of the identity key below. |
| `construct_variant` | `str:utf-8` | scalar | Construct / variant name. Part of the identity key. |
| `dye` | `str:utf-8` | scalar | Dye pair label. Part of the identity key. |
| `ligand` | `str:utf-8` | scalar | Ligand name. Part of the identity key. |
| `ligand_concentration` | `f8` | scalar | Numeric concentration **in the unit given by the next field**. `NaN` is the "absent" sentinel and round-trips back to the same `condition_id`. |
| `ligand_concentration_unit` | `str:utf-8` | scalar | Unit string for the value above, e.g. `nM`. Part of the identity key. |
| `buffer` | `str:utf-8` | scalar | Buffer description. Part of the identity key. |
| `temperature_c` | `f8` | scalar | Temperature in **degrees Celsius**. `NaN` = absent. |
| `laser_power` | `f8` | scalar | Laser power. **Never produced by the filename parser** — `parse_filename` fills only construct/variant, dye, ligand, concentration and unit (`src/tether/io/filename.py`), so this is `NaN` in any store built purely from filenames; it is entered in the conditions editor. **No unit is stored** and there is no companion `laser_power_unit` field, though the conditions UI *displays* the value as mW ([`_key_summary`](https://github.com/bioedca/tether/blob/main/src/tether/gui/conditions.py), `src/tether/gui/conditions.py`). `NaN` = absent. |
| `date` | `str:utf-8` | scalar | Acquisition date. Within-condition provenance; **not** part of the identity key. |
| `replicate` | `str:utf-8` | scalar | Replicate label. Within-condition provenance; not part of the identity key. |
| `leakage_alpha` | `f8` | scalar | Per-condition leakage α, dimensionless. `NaN` when unset. |
| `leakage_alpha_source` | `str:utf-8` | scalar | Provenance of the value above (which donor-only sample it came from). |
| `tags` | `str:utf-8` | scalar | Free-form tag string. |

Three identity-key fields — `buffer`, `temperature_c` and `laser_power` — are part of
the key but are **not** filename-derivable: the only `ConditionKey(...)` construction
in `parse_filename` sets construct/variant, dye, ligand, concentration and unit and
nothing else. In a store whose conditions came from filename parsing alone they are
`""` / `NaN`, and they change only through the conditions editor (a re-key, logged in
`/settings/condition_audit`).

The group also holds an additive child, `/conditions/categories/<condition_id>`: one
resizable 1-D vlen-UTF-8 dataset per condition carrying that condition's ordered,
editable category names ([`_write_category_names`](https://github.com/bioedca/tether/blob/main/src/tether/project/conditions.py) in
`src/tether/project/conditions.py`). It appears only once a category list has been
set; emptying the list resizes the dataset to zero rows rather than deleting it.

Each of those datasets carries one attribute, `tmaven_class_lookup`. It is the condition's
tMAVEN class to category lookup, stored as a JSON object. Its keys are the classes `"1"`,
`"2"`, and so on. Its values are the category names in list order. Class `0` is not stored.
It always means no category (`""`).

The same writer rewrites the attribute with every list
edit, so it never lags the names. The tMAVEN hand-off and its return leg read it through
`read_class_lookup`. The curation hotkeys follow the same numbering. A list saved before the attribute existed reads as the
lookup its order defines. A lookup that disagrees with the names beside it is refused
([ADR-0125](../adr/0125-the-tmaven-class-lookup-follows-the-category-list.md)).

A condition can span several projects ([ADR-0068](../adr/0068-a-project-holds-one-experiment.md)),
and each project keeps its own copy of this list. `copy_category_list` in
`src/tether/project/conditions.py` writes one project's list for a condition into another
project that holds the same condition, in the same order, so every category keeps its integer
code. The destination's previous list is replaced; an empty source list empties it. Molecules
keep their stored category names, so a name that is not in the new list can stay on a molecule.
`compare_category_lists` reports each category whose name or code differs between the two
projects. Both refuse a project that has no `/conditions` row for the condition and name that
file in the message.

| Field | Type | Shape | Meaning / units |

| `weight` | `f8` | scalar | Effective training weight, dimensionless. Human labels are `1.0`; provisional weights decay as human labels accrue and this column is **rewritten** at retrain. |
| `label_value` | `i4` | scalar | The same signed codec as `curation_label`: `0` uncurated, `1` accept, `-1` reject. |

### `/labels/reject_log` — the reason of each reject

A resizable 1-D compound dataset, **append-only**, created on the first human reject
(`reject`, `src/tether/project/labels.py`), so a fresh store does not have it
([ADR-0104](../adr/0104-a-reject-reason-log-under-labels.md)). Each
human reject appends a `reject` row and each un-reject appends a `restore` row.

A rejected trace stays in the store: a reject sets `curation_label` to `-1` and deletes
nothing. The log is a record only. The curation filter, the ranker and every analysis
read `/molecules.curation_label` and not the reason. Provisional-source rejects write
no row. `reject_record_of` returns the `reject` row that joins the molecule's
latest human `/labels` event when that event is a reject, or `None` (also for a store
written before this log existed).

The rows travel with their `/labels` rows. A subset export copies the rows of the exported
molecules, and the split-file merge-back (`merge_labels`, `src/tether/project/merge.py`)
appends the rows that join a `/labels` row it pulls, under the owner's `condition_id`, unless
the owner already holds them. A second pull of the same file appends nothing. A join that names
two pulled rejects (or two restores) copies no reason, since it cannot say which one the reason
belongs to.

| Field | Type | Shape | Meaning / units |
|---|---|---|---|
| `molecule_key` | `str:utf-8` | scalar | Join key into `/molecules.molecule_key`. |
| `event` | `str:utf-8` | scalar | `reject` or `restore`. |
| `reason` | `str:utf-8` | scalar | A code from the list below; empty on a `restore` row. |
| `note` | `str:utf-8` | scalar | Optional free text (valid UTF-8, no NUL character; anything else is refused before the reject or restore is written). |
| `value` | `f8` | scalar | The score threshold of a `threshold` reject; `NaN` on all other rows. |
| `labeler` | `str:utf-8` | scalar | Who rejected or restored. The same value as the matching `/labels` row. |
| `timestamp` | `str:utf-8` | scalar | When. The same value as the matching `/labels` row, so the two rows join on `molecule_key` + `labeler` + `timestamp`. |
| `condition_id` | `str:utf-8` | scalar | The condition of the matching `/labels` row. |

The reasons are a fixed list, defined once in `REJECT_REASONS`
(`src/tether/project/labels.py`). Any other value is refused before a write.

| Code | Meaning |
|---|---|
| `unspecified` | No reason was given. The default of a reject. |
| `no-anticorrelation` | Donor and acceptor do not anti-correlate. |
| `multiple-molecules` | More than one donor or acceptor in the spot. |
| `artifact` | A blink, spike, drift or other artifact makes the trace unusable. |
| `low-signal` | The signal is too low or too noisy to use. |
| `threshold` | Rejected by a score threshold. The row must carry the threshold in `value`. |
| `other` | Another reason. The row must carry a `note` that says which. |

## `/generations` — the trace generations of each movie

Group holding `/generations/table` (`GENERATIONS_DTYPE`, 9 fields), new in
`schema_version` 2 ([ADR-0136](../adr/0136-a-new-extraction-of-a-movie-is-a-new-trace-generation.md)).
Each extraction of a movie appends one row, **append-only**: `write_extraction` writes
generation 1 of a new movie, and `write_generation` (run by `reextract_movie`,
`src/tether/project/extract.py`) a later one. The newest generation of a movie is its
**active** generation: its molecules are the movie's rows of `/molecules`, `/traces` and
`/patches`, so every reader of those arrays reads it. A movie with no row (every movie of
a store stamped `1`) reads as its generation 1, and reading writes nothing. The readers
are in `src/tether/io/generations.py`: `read_generations`, `active_generation`,
`read_generation`.

| Field | Type | Shape | Meaning / units |
|---|---|---|---|
| `movie_id` | `str:utf-8` | scalar | Join key into `/movies.movie_id`. |
| `generation` | `i4` | scalar | The generation's number among the movie's, from `1`. |
| `generation_id` | `str:utf-8` | scalar | `gen-<uuid4 hex>`, unique in the project. It is the identity of the movie's `trace_generation` instance in `/settings/recorded_inputs` (ADR-0103). |
| `created_utc` | `str:utf-8` | scalar | ISO-8601 UTC, e.g. `2026-11-19T18:02:11Z`. It is `""` for the generation 1 of a store stamped `1`, which is recorded when that store first takes a new generation. |
| `inputs` | `str:utf-8` | scalar | JSON: `source` (`sha256`, `uri`, `file_size`, `mtime`), `geometry` (the crop, rotation and flip fields of `/movies`), `layout` (the `/movies/layouts` record or `null`), `map` (`calibration_id`), `colocalization` and `options` (the movie's settings profile). |
| `n_molecules` | `i4` | scalar | The generation's molecule count. |
| `carried_keys` | `str:utf-8` | scalar | JSON list of the `molecule_key` of each molecule whose curation label, category and analysis window were carried from the previous generation. It is `[]` for a first generation. |
| `match_px` | `f8` | scalar | The donor distance, **pixels**, that decided "did not move" for the carried molecules (`GENERATION_MATCH_PX`, `0.5`). It is `NaN` for a first generation. |
| `app_version` | `str:utf-8` | scalar | The writing Tether version. |

When a movie gains a generation, the one that was active is first copied, unchanged, to
`/generations/archive/<movie_id>/<generation>`: `movie` (its `/movies` row), `molecules`,
`acceptor_detected`, `traces/<layer>` (cut to the movie's frame count), `patches/<layer>`
and, if the movie had one, `layout` (its `/movies/layouts` record). Its rows then leave the
row-aligned arrays and the new generation's are appended **at the end**, so the rows of
other movies move up but are not changed. An archive is written once and never changed or
removed by an extraction.

A new generation keeps the movie's `condition_id` when every molecule of the previous
generation had one. When the previous generation has no molecule, the newest archived
generation of the movie that has molecules gives it. A new generation of a project whose
correction state is `ANALYSIS_READY` or `CORRECTED_REVIEW` also appends one row to
`/settings/correction_transitions`, to `CALIBRATION_STALE`, with the actor `policy`. While
an approval is in force (`CALIBRATION_APPROVED`, `CORRECTED_REVIEW`, `ANALYSIS_READY`), it
also appends to `/settings/stale_marks` a mark for the approved `factor_version` (edge 7) and
the applied `correction_version` (edge 8), so *finish review* refuses until the factors are
approved again
([ADR-0136](../adr/0136-a-new-extraction-of-a-movie-is-a-new-trace-generation.md), #1284).

`/generations/label_reviews` is an optional append-only dataset. Each row stores the
current `molecule_id` (UTF-8) and `label_event` (signed 64-bit integer), the zero-based
row index of a human accept or reject in `/labels/table`. A value of `-1` marks a
carried label that is pending review after a clear or in an exported subset. The
last review row for a molecule applies. A carry-over in `carried_keys` starts pending
and stays out of supervised training until confirmed on the current extraction.

## `/sources` — the source registry

Group holding `/sources/table` (`SOURCES_DTYPE`, 13 fields), new in `schema_version` 3

One row for each source file of the project: a movie, the bead video that made a channel

from its `/movies` row, with the id `movie:<movie_id>`, the stored `uri` as its path and the
checksum not calculated. Reading writes nothing. The first write that needs the record
stores it.

| Field | Type | Shape | Meaning / units |
|---|---|---|---|
| `source_id` | `str:utf-8` | scalar | `src-<uuid4 hex>`, or `movie:<movie_id>` for a record first made from `/movies`. Unique in the project. |
| `relative_path` | `str:utf-8` | scalar | The file's path, read against the project file's folder, with `/` separators. A file on another drive keeps its absolute path. |
| `original_name` | `str:utf-8` | scalar | The file name at registration. |
| `file_size` | `i8` | scalar | **Bytes.** |
| `sha256` | `str:utf-8` | scalar | Lower-case hex SHA-256 of the file, or `""` while the checksum is not calculated. |
| `adapter` | `str:utf-8` | scalar | The adapter that reads the file, or `""`. |
| `adapter_version` | `str:utf-8` | scalar | That adapter's version, or `""`. |
| `role` | `str:utf-8` | scalar | `movie`, `bead_video` or `map_image`. |
| `acquisition` | `str:utf-8` | scalar | JSON object of acquisition values, or `{}`. |
| `movie_id` | `str:utf-8` | scalar | Join key into `/movies.movie_id` for a movie, else `""`. |
| `derived_from` | `str:utf-8` | scalar | The `source_id` of the original a derived file was made from, or `""` for an original. |
| `recipe` | `str:utf-8` | scalar | The recipe that made the derived file from its original, or `""` for an original. |
| `created_utc` | `str:utf-8` | scalar | ISO-8601 UTC time the row was first stored. |

**The checksum** is calculated by a stored job (`/settings/jobs`, command `source-checksum`)
with one part for each source. It reads in 1 MiB blocks, with progress and cancel. A file
whose checksum differs from the one already known (the registry's or `/movies.sha256`) fails
its part, and nothing is written.

**A source that moved** is linked again with `relink_source` only when the checksums match.
The new file must have the registry's checksum or, for a movie with none, its `/movies.sha256`.

**A copy for sharing** (`export_subset_tether(..., curator_alias=...)`) copies the registry. It keeps
only the file name of a path that is absolute or steps out of the folder (`..`). A plain
subset stores each path relative to its own folder, so it names the same file.

## `/traces` — the integrated intensity arrays

Empty in a fresh store. **Up to six** datasets, named
`{donor,acceptor}_{raw,corrected,background}`
([ADR-0016](../adr/0016-extraction-trace-store-layout.md)); `write_extraction` writes
all six **only for a movie that yielded at least one molecule**. A movie that
colocalized zero molecules still appends its `/movies` row, but creates no
`/traces` or `/patches` dataset at all
(`if molecules.n_molecules:`, `src/tether/imaging/extract.py`) — so a valid,
error-free store can have a populated `/movies` and an entirely empty `/traces`.
The other provenances write fewer layers:

| Dataset | Content |
|---|---|
| `donor_raw`, `acceptor_raw` | Uncorrected aperture sum, before background subtraction. |
| `donor_corrected`, `acceptor_corrected` | Background-subtracted disk intensity, exactly `raw − background`. |
| `donor_background`, `acceptor_background` | The subtracted background: the ring mean of a temporal moving average of the crop, **already scaled by the disk pixel count** `n_psf` (`tether.imaging.aperture`). |

Whichever are present are `(n_molecules, max_T)`, dtype **float32**
([`_TRACE_DTYPE = "<f4"`](https://github.com/bioedca/tether/blob/main/src/tether/imaging/extract.py), `src/tether/imaging/extract.py`), chunked and
gzip-compressed, with `maxshape=(None, None)`. **Do not assume all six exist** — see
the zero-molecule case above and the last two bullets below.

- **In a natively appended store the time axis is zero-padded to the longest movie in
  that store.** Appending a shorter movie leaves zeros past its end; appending a
  longer one grows the axis and zero-fills the tail of every existing row
  ([`_append_padded_2d`](https://github.com/bioedca/tether/blob/main/src/tether/imaging/extract.py)). A **subset export** instead inherits the *source* store's
  width — [`_copy_trace_layers`](https://github.com/bioedca/tether/blob/main/src/tether/project/export.py) copies `ds[rows]` with the source dataset's full second
  dimension (`src/tether/project/export.py`) — so a subset's width need not match the
  longest movie behind its own molecules, and it has no `/movies` rows to check
  against. In every case the valid extent of row `i` is `/molecules.frame_range[i]` —
  use it, do not infer it from where the zeros start.
- Row order matches `/molecules/table` exactly.
- The time axis unit is **frames**; seconds-per-frame lives only in
  `/movies.frame_time`.
- The intensity axis carries **no recorded physical unit or gain**, and nothing in
  the code states a calibration, so do not assume one. What the numbers *are* depends
  on the store's provenance: in a natively extracted store they are aperture sums of
  raw pixel values (`tether.imaging.aperture.integrate_traces`) in whatever the source
  pixel dtype held (`/movies.pixel_dtype`, `/movies.byteorder`); in a **Deep-LASI
  reconstruction** they are the pre-integrated `.mat` series copied verbatim — the
  aperture integration "is skipped" ([`_traces_from_export`](https://github.com/bioedca/tether/blob/main/src/tether/project/reconstruct.py),
  `src/tether/project/reconstruct.py`) — and in an **analysis-only import** they are
  the SMD/text series copied verbatim. Only the first is a sum Tether itself computed.
- `tether.project.trace_layers.INTENSITY_QUANTITY_LAYERS` is the single source of
  truth for which pair an `intensity_quantity` selects: `corrected` and `raw` only —
  there is no `background` quantity.
- An **analysis-only import** (from a legacy Deep-LASI text or SMD file) writes
  *only* `donor_corrected` and `acceptor_corrected`; the raw and background layers
  are genuinely absent. See [Legacy Deep-LASI import](../io/legacy-import.md).
- A **subset export** (`export_subset_tether`, `src/tether/project/export.py`) writes
  only `donor_corrected`/`acceptor_corrected` unless `include_raw=True`, which is
  **not** the default. The raw and background layers travel or are dropped as a set,
  deliberately: `corrected = raw − background` exactly, so keeping background would
  make raw reconstructable and defeat the movie-less invariant. Detect it from
  the `tether_subset_include_raw` root attribute.

## `/patches` — the cached image crops

Empty until `write_extraction` runs **on a movie with at least one molecule** —
a zero-molecule movie creates neither dataset, as under `/traces` above.
Two datasets, `donor` and `acceptor`, each
`(n_molecules, window, window)` float32, chunked and gzip-compressed, with
`maxshape=(None, window, window)` — only the molecule axis grows, because the
aperture window is fixed per project and validated on every later append.

In a **natively extracted** store each entry is the **temporal mean** image crop for
that molecule and channel, in `(row, col)` image order, centered on the molecule's
rounded coordinate. [`_mean_patches`](https://github.com/bioedca/tether/blob/main/src/tether/imaging/extract.py) (`src/tether/imaging/extract.py`) zero-fills a
molecule whose aperture window falls outside the frame, but no such molecule reaches disk:
`colocalize` keeps only molecules whose aperture window fits in **both** channels, and
`write_extraction` refuses the whole write if any integrated trace is invalid
([`_validate_alignment`](https://github.com/bioedca/tether/blob/main/src/tether/imaging/extract.py) — "refusing to write an all-zero trace"). The default aperture window is 21 px
(`extract_molecules(..., window=21)`); the value actually used is recorded as
`/settings/extraction@window`. Row order matches `/molecules/table`. A subset export
carries both stacks, row-subset to the exported molecules; **analysis-only imports
leave `/patches` empty**, because they have no coordinates.

> **A Deep-LASI reconstruction's patches are placeholders, not images.**
> `reconstruct_project` accepts optional `donor_patches`/`acceptor_patches`, and
> [`_resolve_patches`](https://github.com/bioedca/tether/blob/main/src/tether/project/reconstruct.py) (`src/tether/project/reconstruct.py`) **zero-fills** an
> `(n_molecules, 21, 21)` stack for whichever is `None` — the movie link makes the real
> crops re-cacheable later. No shipped caller passes them (the GUI wizard's
> `reconstruct_project` call omits both), so in practice **every** reconstructed store's
> `/patches` are entirely zero: a real reconstruction of the committed 4-molecule
> UCKOPSB `.mat` writes `donor` and `acceptor` of shape `(4, 21, 21)` float32 with
> `max() == 0.0`. Do **not** read an all-zero patch as an out-of-frame crop in any
> store: the native writer rejects those before they reach disk, so a zero patch is
> either a reconstruction placeholder or a genuinely dark in-frame crop. Check the
> store's provenance first — `/settings/extraction@profile_json` carries
> `"source": "m7-deeplasi-reconstruction"` for this path — rather than inferring
> anything from the pixels.

## `/settings` — provenance of each pipeline stage

Empty until a stage runs. Every child is a **group carrying scalar attributes and no
datasets**, except `condition_audit`, `molecule_audit`, `lock_takeovers`, `jobs`,
`recorded_inputs`, `stale_marks`, `correction_transitions`, `gamma_contributors`,
`gamma_contributor_decisions` and `approvals`, which are datasets.

| Child | Written by | Lifecycle |
|---|---|---|
| `extraction` | `write_extraction` (`src/tether/imaging/extract.py`) | **Write-once** per project; later movies must match the recorded parameters or the write is rejected. Its child group `movies` gains one attribute per movie (below). |
| `correction` | `compute_corrected_fret` (`src/tether/project/correct.py`) | Replaced on each pass. |
| `leakage` | `compute_leakage_alpha` (`src/tether/project/leakage.py`) | Replaced on each pass. |
| `gamma` | `compute_gamma` (`src/tether/project/gamma.py`) | Replaced on each pass. **Removed** by a `compute_leakage_alpha` pass that withholds α, because that pass resets the processed `gamma` rows to `NaN`; absent therefore means no current γ pass. |
| `batch` | `run_batch` (`src/tether/project/batch.py`) | Replaced on each run; adds one `<stage>_status` attribute per stage. |
| `analysis_only` | `import_analysis_only_project` (`src/tether/project/analysis_import.py`) | Marker that movie round-trip is unavailable for this store. |
| `condition_audit` | `tether.project.conditions` | A **dataset**: append-only re-key/merge log, created lazily. |
| `molecule_audit` | `tether.project.molecule_edits` | A **dataset**: append-only log of per-molecule category and analysis-window edits, created lazily. |
| `lock_takeovers` | `tether.project.lock_takeovers` | A **dataset**: append-only log of each successful lock Recover or Take over, created lazily (ADR-0121). |
| `jobs` | `tether.project.jobs` | A **dataset**: one row per job, created lazily; a row changes as its job runs. |
| `recorded_inputs` | `tether.project.jobs` | A **dataset**: append-only identities of the inputs of each record, created lazily. |
| `stale_marks` | `tether.project.jobs` | A **dataset**: append-only stale marks, created lazily; a mark is never removed. |
| `correction_transitions` | `tether.project.correction_states` | A **dataset**: append-only transitions of the correction states of G03, created lazily (ADR-0131). |
| `gamma_contributors` | `compute_gamma` (`src/tether/project/gamma.py`) | A **dataset**: the γ evidence table, one row for each examined molecule (#927). Replaced on each γ pass, and removed with `gamma` by a `compute_leakage_alpha` pass that withholds α. |
| `gamma_contributor_decisions` | `tether.project.gamma_contributors` | A **dataset**: append-only exclusions and inclusions of γ contributors by a person or a recipe policy, created lazily (#927). |

`/settings/extraction` is the one most readers need, because it records the
integration geometry behind `/traces` and `/patches`. In a **Deep-LASI
reconstruction** the same attributes are written from the standard 21 px defaults and
"describe the *provenance* of the layers, not a fresh integration this module
performed" (`src/tether/project/reconstruct.py`) — the traces were integrated by
Deep-LASI, not by Tether:

| Attribute | Type | Meaning / units |
|---|---|---|
| `window` | int | Patch/aperture window edge, **pixels** (default 21). |
| `disk_radius` | float | Signal-disk radius, pixels. |
| `ring_inner`, `ring_outer` | float | Background annulus radii, pixels. |
| `bg_window` | int | Background moving-average length, **frames**. |
| `n_psf` | int | Number of pixels in the disk mask (derived from the radii). |
| `molecule_key_quantum_px` | float | The `molecule_key` coordinate quantum, pixels (`0.1`). |
| `app_version` | str | Writing Tether version. |
| `profile_json` | str | The caller's settings profile as JSON, with the `colocalization` rule the writer stamps from a detected molecule list (ADR-0127) — present only when there is a profile or a rule to record. |

The stamp describes only the first extraction. So each movie's own settings profile is also
kept on the child group **`/settings/extraction/movies`**. It holds one string attribute per
movie, named by its `movie_id`, with that movie's profile as JSON. The first movie gets one
too. A movie appended later records its `.tmap` and `.tdat` sources, detection mode and
registration verdict there.

The appends are `add_movie_to_project`
(`src/tether/project/extract.py`) and `add_reconstruction_to_project`
(`src/tether/project/reconstruct.py`). The stamp above does not change.
`read_movie_settings` (`src/tether/imaging/extract.py`) returns the record as
`{movie_id: profile}`. A project written before this record existed has no `movies` child.
It reads as `{}`
([ADR-0117](../adr/0117-a-movie-is-appended-to-a-project-once-under-its-writer-lock.md)).

`/settings/condition_audit` is a resizable 1-D compound dataset with the fields
`event` (`rekey` or `merge`), `from_condition_id`, `to_condition_id`, `n_molecules`
(`i8`), `labeler`, `timestamp`, `reason`, `app_version` — all strings except
`n_molecules` ([`_audit_dtype`](https://github.com/bioedca/tether/blob/main/src/tether/project/conditions.py) in `src/tether/project/conditions.py`). It is
append-only and never rewritten.

`/settings/molecule_audit` is a resizable 1-D compound dataset with one row for each
`/molecules` row an edit changed ([`_audit_dtype`](https://github.com/bioedca/tether/blob/main/src/tether/project/molecule_edits.py) in `src/tether/project/molecule_edits.py`):
`event` (`set_category`, `clear_category`, `set_analysis_window` or
`reset_analysis_window`), `molecule_id`, `molecule_key`, `condition_id`, `old_category`,
`new_category`, `old_window` and `new_window` (`i4`, shape `(2,)`, `[start, stop)` frame
indices), `labeler`, `timestamp`, `reason` and `app_version`. A category row carries
`[-1, -1]` in both window fields, and a window row carries `""` in both category fields. The
row is written **before** the `/molecules` field changes, and an edit that changes
nothing writes no row. Category edits are logged here and **not** in `/labels`, whose
`label_value` is the accept/reject codec.

`/settings/lock_takeovers` is a resizable 1-D compound dataset with one row for each
successful lock takeover ([`_dtype`](https://github.com/bioedca/tether/blob/main/src/tether/project/lock_takeovers.py) in `src/tether/project/lock_takeovers.py`, ADR-0121):
`timestamp` (the new lock's UTC acquisition instant), `action` (`recover` or `take_over`),
`holder_user`, `holder_host`, `holder_pid` (`i8`), `ousted_corrupt` (`u1`, `1` when the ousted
lock could not be parsed), `ousted_user`, `ousted_host`, `ousted_pid` (`i8`),
`ousted_timestamp` and `app_version`. A corrupt ousted lock carries `""`, `""`, `-1` and `""` in
the four `ousted_*` holder fields. The row is written after the project has been reopened
writable under the new lock, so a refused or failed takeover writes none. It is append-only and
never rewritten.

### Jobs, recorded inputs and stale marks

`/settings/jobs` holds one row for each job of the job and dependency coordinator
([ADR-0126](../adr/0126-jobs-and-stale-marks-are-stored-in-the-project.md)). Every field is a
UTF-8 string: `job_id` (32 hex characters), `command` and `request` (the service request in
its text form, ADR-0100), `state`, `parts` and `completed` (JSON arrays of part names, and
the second is the checkpoint), `inputs` (a JSON object from `"<node key>:<instance id>"` to the
identity of that input), `owner` (JSON: `host`, `user`, `pid` and the lock `nonce` of the
writer that last ran the job), `created_utc`, `started_utc`, `ended_utc` (ISO-8601 UTC, `""`
when not reached), `error` and `app_version`. The `state` is one of:

| State | Meaning |
|---|---|
| `queued` | Stored and not started. |
| `running` | A writer session is doing the parts now. |
| `done` | Every part is complete. |
| `failed` | A part raised an error; `error` says which and why. A retry continues from `completed`. |
| `cancelled` | Stopped by the user; the complete parts are kept. A retry continues from `completed`. |
| `interrupted` | It was running when its owner stopped. A retry continues from `completed`. |

A stored `running` row can outlive its writer: the lock no longer carries its `nonce`, or its
process on this computer is not running. Such a row is **read** as `interrupted`, and the next
writer stores it so. A reader needs no lock and the file is closed between parts, so a reader
never waits on a job.

`/settings/recorded_inputs` has the string fields `node`, `instance`, `upstream_node`,
`upstream_instance` and `identity`: one row for each direct input of a record of the
dependency graph ([ADR-0103](../adr/0103-the-project-dependency-graph-and-the-stale-rules.md)),
written once when the record is made. `/settings/stale_marks` has the string fields `node`,
`instance`, `edge` (the edge number of ADR-0103), `upstream_node`, `upstream_instance`,
`edited_node`, `edited_instance`, `event`, `timestamp` and `app_version`. A record with a mark
is stale: it stays readable and never supplies a current result. Both are append-only.

### Correction states

`/settings/correction_transitions` holds one row for each transition of the correction states
of diagram G03 ([ADR-0131](../adr/0131-the-correction-states-are-a-transition-log-in-the-project.md)).
Every field is a UTF-8 string: `scope` (the calibration scope, `project`), `from_state` and
`to_state` (a state name such as `GAMMA_REVIEW`), `event` (such as `approve`), `by` (`person` or
`policy`), `actor` (the person's name, or the policy text of the recipe), `detail` (a JSON
object with the values the guard read: `alpha`, `gamma`, `source`, `factor_version`,
`correction_version`, the `guard` and `action` of the edge, and `start_proposal` on the first
row of a project that already held factors), `timestamp` (ISO-8601 UTC) and `app_version`. The
present state of a scope is the `to_state` of its last row, and the rows are append-only.

A scope with no row is in its start state: `APPARENT_REVIEW`, or `GAMMA_REVIEW` when
`/settings/leakage`, `/settings/gamma` or `/settings/correction` exists. Such a project never
reads as approved. A corrected analysis is refused in every state except `ANALYSIS_READY`, and an
apparent-E analysis is never refused.

### γ evidence table

`/settings/gamma_contributors` holds one row for each molecule that the last γ pass examined
([#927](https://github.com/bioedca/tether/issues/927)), in `/molecules` order.

| Field | Meaning |
|---|---|
| `molecule_key` | The molecule. |
| `step`, `step_source` | The absolute acceptor-bleach frame, and where it came from. Today it is always `detector`. A window that a person sets comes with the calibration windows of [#928](https://github.com/bioedca/tether/issues/928). |
| `level_window`, `half_window` | The level window that averaged the intensities: `half-window` with its half-width, or `whole-segment` with `half_window = 0`. |
| `pre_window`, `post_window` | The absolute half-open frame ranges of the two levels. |
| `alpha` | The leakage factor that corrected the acceptor levels of the row. |
| `donor_pre`, `donor_post`, `acceptor_pre`, `acceptor_post` | The four levels. The acceptor is leakage-corrected. |
| `delta_donor`, `delta_acceptor` | ΔI_D and ΔI_A. |
| `ratio` | The raw ΔI_A / ΔI_D, with its sign. |
| `gamma` | The trace γ. It is `NaN` when the gates exclude the row. |
| `gate` | The estimator's reason: `ok`, `no-step`, `short-pre`, `short-post`, `degenerate-donor` or `out-of-range`. |
| `included`, `reason`, `by`, `actor` | Whether the row is in the median, and the reason, author kind (`estimator`, `person` or `policy`) and author of an exclusion. |

With the stored traces and the row's `alpha`, the windows give each row again, also after a
later leakage pass changes `/molecules.alpha`. An excluded row keeps its `ratio`, also when
it is negative, zero or above the ceiling. The `ratio` is `NaN` only when no step was
measured (`no-step`, `short-pre` or `short-post`), or when ΔI_D is zero. Then the `reason`
is `zero-donor-step`, followed by a semicolon and the reason of a person or a policy that excluded
the row.

The population γ is the median of the included rows. It is withheld below `min_qualifying_traces` included rows, so with no
decision it is the γ that `compute_gamma` gave before the table. `/settings/gamma` counts the
decisions in `n_excluded`.

`/settings/gamma_contributor_decisions` has the fields `molecule_key`, `included`, `reason`,
`by` (`person` or `policy`), `actor`, `timestamp` and `app_version`. The latest row for a
`molecule_key` holds, and each γ pass reads it. `set_gamma_contributor` writes the decision
and the new γ pass in one guarded write. An exclusion needs a reason. An inclusion withdraws
a decision but never a gate. The correction state follows the change:

- In `CALIBRATION_APPROVED` the evidence is frozen and the change is refused.
- In `CORRECTED_REVIEW` and `ANALYSIS_READY` the change is the evidence-change event, and the
  state becomes `CALIBRATION_STALE`.
- In `GAMMA_REVIEW` a withheld γ moves the state to `CALIBRATION_BLOCKED` before the write,
  so a failed event writes nothing. In `CALIBRATION_BLOCKED` a valid γ moves it back to
  `GAMMA_REVIEW` after the write, and the same decision again sends an event that failed.

### Approvals

`/settings/approvals` is a resizable compound dataset with one row for each approval of a step
that needs a person ([ADR-0102](../adr/0102-a-batch-run-stops-at-an-approval-step-or-applies-a-recipe-policy.md),
section 4). Every field is a UTF-8 string: `step` (`map.accept`, `alpha.confirm`, `gamma.approve` or
`fit.select`), `subject` (the map, the condition or the analysis set), `by` (`person` or
`policy`), `actor` (the person's name, or the policy text exactly as the recipe gives it),
`recipe_sha256` and `recipe_version` (the identity of the recipe whose run asked for the
approval, or `""` and `0` for an approval that no recipe run asked for), `report` (a JSON object of
each evidence file name, the report's JSON and its PNG images, to its SHA-256), `timestamp`
(ISO-8601 UTC) and `app_version`. Only an approval writes a row: a policy whose rule does not
approve writes none. The rows are append-only.

A recipe run (`tether run`) stores jobs for steps that write a project in its `/settings/jobs`
while recording progress for steps that write no project in the per-user checkpoint.
The job's single part is a JSON object with `recipe_sha256`, `recipe_version` and `step` (the
step number). Jobs written by the current runner also store `run_id` and `attempt_id` to
identify the run and step attempt.
`--resume` checks project jobs against the recipe checkpoint in Tether's per-user state.
A step that stopped at an approval step is stored `cancelled`, with the requested step and
subject in the cancellation reason so a later approval can identify its recipe.

## `/idealization` — one subgroup per fitted model

Empty until an idealization runs. Each fit lands in `/idealization/{model_name}`
([ADR-0024](../adr/0024-idealization-store-layout-staleness-and-nstates.md)), staged
first as `{model_name}.__writing__` and then swapped in by **delete-then-rename**.
The staged group is complete before the swap, so a real model name never holds a
half-written fit — but the swap itself is **not fully atomic**: HDF5 has no atomic
in-file rename-over, so a crash in the interval between removing the old model and
renaming the staged one can leave *only* the `.__writing__` group and no model at all
(`write_idealization_model`, `src/tether/project/idealize.py`). Re-running the write
repairs it. A reader should normally skip a name ending in `.__writing__` — but must
not treat its presence as proof that a good model exists alongside it.

`n_fitted` below is the number of molecules **this fit covered**, which is *not* the
store's molecule count and *not* the store's row order — see the note under the table.

| Member | Shape | Dtype | Present |
|---|---|---|---|
| `mean` | `(nstates,)` | float64 | always — the state FRET levels, dimensionless E |
| `var` | `(nstates,)` | float64 | when the fit produced variances |
| `tmatrix` | `(nstates, nstates)` | float64 | optional — unnormalized transition counts |
| `norm_tmatrix` | `(nstates, nstates)` | float64 | optional — row-normalized transition probabilities |
| `rates` | `(nstates, nstates)` | float64 | optional — per-frame rates |
| `pi` | `(nstates,)` | float64 | optional — the **unnormalized** Dirichlet posterior; it sums to roughly the trace count and is *not* a probability vector |
| `frac` | `(nstates,)` | float64 | optional — the normalized populations; **use this for plots and exports**, not `pi` |
| `priors/<name>` | `(nstates,)` or `(nstates, nstates)` | float64 | optional subgroup — the variational prior hyperparameters |
| `idealized` | `(n_fitted, n_frames)` | float64, gzip | always — per-frame idealized FRET level, `NaN` outside each molecule's analysis window |
| `state_path` | `(n_fitted, n_frames)` | int64, gzip | always — state index, `-1` (`tether.idealize.NO_STATE`) outside the analysis window |
| `molecule_key` | `(n_fitted,)` | vlen UTF-8 | always |
| `molecule_id` | `(n_fitted,)` | vlen UTF-8 | always — the **unique** join key for staleness and export |
| `input_hash` | `(n_fitted,)` | vlen UTF-8 | always — see below |

> **The per-molecule rows are a selection, not the store.** Unlike `/traces` and
> `/patches`, whose row order matches `/molecules/table` positionally, these five
> arrays cover only the molecules included in this fit: the writer sizes them from
> `len(molecule_keys)` and stamps that count as the group's `n_molecules` attribute.
> A subset export narrows them further. **Join on `molecule_id`** — never index them
> with a `/molecules/table` row number. A real store with 3 molecules, idealized over
> 2 of them, holds `idealized` of shape `(2, 40)` and `n_molecules = 2`.

The `priors/` subgroup is not uniformly 1-D. The canonical member names, enumerated
in `src/tether/idealize/driver.py`, are `a_prior`, `b_prior`, `beta_prior`,
`mu_prior` and `pi_prior` — all `(nstates,)` — plus `tm_prior`, the transition-matrix
Dirichlet prior, which is `(nstates, nstates)`. Read each member's own shape; do not
size a buffer from `nstates` alone.

The `pi` / `frac` distinction is the full Appendix-D.2 population model
([ADR-0041](../adr/0041-population-model-and-ebfret.md)).

`input_hash` is a per-molecule composite hash of everything the fit consumed: the
windowed donor/acceptor input, the `intensity_quantity`, the analysis-window bounds,
and the molecule's **effective applied** α and γ. The `correction_method` string is
*not* folded into the digest itself: `input_provenance_hash` passes it through
[`_effective_factors`](https://github.com/bioedca/tether/blob/main/src/tether/project/idealize.py) (`src/tether/project/idealize.py`), which maps every apparent-E
method — `""`, `apparent-E (corrections unavailable)` and `apparent-E (user toggle)` —
to the identity `(α = 0, γ = 1)`, and only the resulting pair is hashed. So a row
moving between those three methods keeps the **same** `input_hash`, deliberately: the
corrected E it would feed is never displayed, so nothing it feeds went stale. Fold the
method string in yourself and you will falsely mark live idealizations stale. A real
correction change re-stales exactly the dependent idealizations, with per-factor scope
([ADR-0029](../adr/0029-idealization-correction-provenance-hash-and-per-factor-staleness.md)).

Group attributes: `type`, `nstates`, `dtype` (the idealized quantity, e.g. `FRET`),
`intensity_quantity`, `nstates_selected_by`, `n_molecules` (the **fitted** count,
i.e. `n_fitted` above, not the store's molecule count), `app_version`,
`created_utc`, plus `elbo` and `elbo_by_nstates` (a JSON string) when the fitter
produced them. These names are reserved — a caller's `extra_attrs` may not override
them ([`_RESERVED_MODEL_ATTRS`](https://github.com/bioedca/tether/blob/main/src/tether/project/idealize.py)).

## `/features` — the ML feature cache

Empty until `compute_features` runs, which writes `/features/table`: a resizable 1-D
compound dataset of **11 fields** — two id columns, `molecule_id` and `molecule_key`
(both vlen UTF-8), then **exactly one column per `tether.ml.features.FEATURE_NAMES`
entry**, in that order: `n_frames`, `total_intensity`, `snr`, `fret_mean`, `fret_var`,
`anticorr_lag0`, `anticorr_lag1_magnitude`, `neighbor_distance`, `aperture_overlap`.
`n_frames` is a member of that feature list, not a separate column beside it, and it
is the sole **integer** one — `i8`, the only entry in [`_INT_FEATURES`](https://github.com/bioedca/tether/blob/main/src/tether/project/features.py); the other eight
features are `f8` ([`_feature_table_dtype`](https://github.com/bioedca/tether/blob/main/src/tether/project/features.py), `src/tether/project/features.py`).

Units: `n_frames` is frames, `total_intensity` is in the same uncalibrated intensity
units as `/traces`, `neighbor_distance` is pixels, `aperture_overlap` is a fraction,
and the FRET and anticorrelation features are dimensionless. Undefined features are
`NaN`, never fabricated.

Dataset attributes carry `app_version`, `created_utc`, `intensity_quantity`,
`n_molecules`, `feature_names` (a JSON list — the authoritative column order), and
`feature_schema_version`. That last one is **a second, independent version number**
(`FEATURE_SCHEMA_VERSION`, currently `1`) governing the cache layout only; it is not
the store's `schema_version`. The table is a recomputable cache, so a mismatch is a
prompt to recompute, not a migration.

Each row comes from that molecule's traces, sliced to its `analysis_window`. A later
window change makes the row stale. So each writer below deletes the whole table when it
changes the window of a row the table holds. It deletes the table before it writes the
new window. The readers then raise "run compute_features first".

| Writer | Module |
|---|---|
| `set_analysis_window`, `reset_analysis_window` | `src/tether/project/molecule_edits.py` |
| `compute_photobleach` (the auto window) | `src/tether/project/photobleach.py` |
| `apply_reconcile` (an accepted tMAVEN window edit) | `src/tether/project/handoff.py` |

A writer that changes no featured window keeps the table. An SMD analysis import
(`import_analysis_only_project`) also seeds windows, but it builds a new store. The
store it publishes has no feature table, also when it replaces a project that had one.

## `/calibration` — the channel registration maps

Empty until `write_calibration` runs. Each map lands under
`/calibration/<calibration_id>`, referenced by `/movies.calibration_id`, and is
**write-once** per id. Two direction subgroups, `ref_to_moving` and `moving_to_ref`,
each holding four float64 datasets: `a` and `b` (the polynomial coefficient vectors)
and `norm_xy` and `norm_uv` (the `(3, 3)` normalization matrices).

Group attributes record the scalar provenance: `reference_channel`,
`moving_channel`, `rms_residual` (pixels), `n_control_points`, `gate_px` (pixels),
`degree`, `low_confidence`, `source`, `provenance_json`, plus the per-channel
geometry attributes written by [`_write_geometry_attrs`](https://github.com/bioedca/tether/blob/main/src/tether/imaging/calibrate.py)
(`src/tether/imaging/calibrate.py`).

## `/models` — a reference to each condition's model file

`/models` exists in every store because the schema freeze forward-declared it. The
quality ranker itself is **not** in the project. It is a standalone portable model
file that travels with a *condition* across many experiment files
(`src/tether/ml/persistence.py`, ADR-0035). The project only records **where that
file is and which version of it the project last saw**. It keeps one group per
condition, written by
[`record_model_reference`](https://github.com/bioedca/tether/blob/main/src/tether/project/model_artifact.py)
(`src/tether/project/model_artifact.py`, ADR-0119). The group is empty until a model
is saved for a condition the project holds.

`/models/<condition_id>` is a group with no datasets and these attributes:

| Attribute | Type | Meaning |
|---|---|---|
| `reference_version` | int | the layout version of this group (`MODEL_REFERENCE_VERSION`, currently `1`); independent of the store's `schema_version` |
| `condition_id` | str | the condition, the same as the group name |
| `artifact_path` | str | the model file, an absolute path on the machine that saved it |
| `artifact_sha256` | str | the SHA-256 of the model file at that save: compare it with the file to see whether the model changed since |
| `n_retrains` | int | the model's retrain count at that save |
| `model_updated_utc` | str | the model's last fit time (ISO-8601 UTC) |
| `recorded_utc` | str | when this reference was written (ISO-8601 UTC) |
| `app_version` | str | the Tether version that wrote it |

A later save replaces the attributes of that condition's group. A project keeps one
reference per condition. The model file has its own single-writer lock: `<model>.lock`
beside it, the same record as a project's `.lock`. The condition's owner-curator
holds it while they retrain and save.

The reference has no user or host field. Its `artifact_path` is an absolute path, and a
path can still name a user or a host, such as a home folder or a network share. If you
share a project or a subset of it, keep the model under a neutral folder.
Subset export copies the group verbatim (`src/tether/project/export.py`). A missing
`/models` child means "no model recorded". An `artifact_path` that does not exist on
the reader's machine is normal: the file may live on another computer or in a synced
folder.
